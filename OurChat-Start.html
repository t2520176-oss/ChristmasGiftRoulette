기존 작업은 그대로 두세요.

새 Supabase 프로젝트, 새 비공개 GitHub 저장소, 새 Vercel 프로젝트만 사용합니다. 기존 데이터·사이트·도메인·환경변수를 변경하거나 삭제하지 마세요. 이 도우미는 서비스에 로그인하거나 데이터를 전송·저장하지 않습니다.

1. 새 데이터베이스 준비

Supabase 열기
  1. New project에서 OurChat 전용 새 프로젝트를 만드세요.
  2. Authentication에서 이메일 로그인을 사용하고 공개 가입과 익명 로그인을 끄세요.
  3. Authentication → Users에서 두 사용자 계정을 확인 완료 상태로 만드세요.
  4. 두 사람의 User UID / UUID를 아래에 넣으세요. 이메일·비밀번호·API 키를 넣는 칸이 아닙니다.

서로 다른 실제 UUID 두 개를 입력하고 새 프로젝트 여부를 확인하세요.

새 프로젝트의 SQL Editor → New query에 붙여넣고 한 번 실행하세요. 테이블 생성과 두 사람 등록이 함께 처리됩니다. 기존 public 테이블·사용자 함수·private 스키마 등이 있으면 변경 전에 중단합니다. 이 검사는 프로젝트 선택 확인을 대신하지 않습니다. 오류가 나면 기존 데이터를 지우지 말고 내용을 확인하세요.

2. 새 앱 배포 시작

새 Supabase 프로젝트의 URL과 publishable 키를 준비하세요. 아래 버튼은 Vercel의 새 프로젝트 복제 화면을 엽니다.

Vercel에서 새 OurChat 만들기

새 Git 저장소를 Private으로 만들고 새 Vercel 프로젝트를 생성하세요. 같은 이름이 이미 있으면 다른 새 이름을 사용하세요. 기존 프로젝트를 고르거나 기존 도메인을 연결하지 마세요.

Vercel 입력값 안내

NEXT_PUBLIC_SUPABASE_URL: 새 Supabase 프로젝트 URL

NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY: 새 프로젝트의 publishable 키

service_role / secret 키를 publishable 칸에 넣지 마세요. Framework는 Next.js, Node.js는 24.x입니다. 복제된 package.json이 있는 폴더를 Root Directory로 지정하세요.

3. 새 앱 주소 연결

첫 배포 뒤 새 Vercel 프로젝트의 고정 운영 주소를 복사하세요. 아래에 넣으면 환경변수에 쓸 주소를 확인할 수 있습니다.

새 Vercel 프로젝트에 NEXT_PUBLIC_SITE_URL을 추가하고 이 주소를 값으로 넣으세요. Production에 적용한 뒤 Redeploy하세요. 새 Supabase 프로젝트의 Authentication → URL Configuration → Site URL도 같은 주소로 설정하세요.

주소를 설정하고 재배포하기 전에는 로그인과 메시지 전송이 준비되지 않습니다. 기존 프로젝트의 도메인이나 환경변수는 바꾸지 마세요.

4. 앱 열고 설치

두 계정으로 로그인하여 양방향 메시지를 확인한 뒤, 열린 앱에서 Edge·Chrome의 앱 설치 메뉴를 누르세요. 이후에는 앱 아이콘으로 실행합니다. 휴대폰에서는 같은 새 HTTPS 주소를 열어 설치하세요.

현재 배포·실제 채팅·Windows 기기 설치는 완료되었다고 확인하지 않았습니다. 이 파일은 설정과 설치 경로를 모아 둔 도우미입니다. 푸시 알림 설정은 별도 단계입니다.

입력값은 이 창에서만 사용합니다. 창을 닫으면 사라집니다. 비밀번호와 서비스 비밀 키는 이 파일이나 대화에 입력하지 마세요.
