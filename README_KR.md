# FigureCraft – AI 3D 피규어 메이커

글(프롬프트)로 **3D 프린터용 피규어**를 만드는 Windows 프로그램입니다.
귀여운 캐릭터, 동물, 판타지 생물, 장식품처럼 **곡선이 많은 유기적인 형태**에 집중합니다.

```
글 설명 → (클라우드 GPU) AI 3D 생성 → GLB → 메시 정리 → 출력 최적화
       → 색 줄이기(최대 1~4색) → Bambu Studio용 3MF / STL / GLB 내보내기
```

> **중요 – 먼저 읽어 주세요**
> * 내 PC(Radeon 760M)는 큰 3D AI 모델을 돌릴 수 없습니다. 그래서 **AI 생성은 클라우드 GPU**에서 하고, 이 프로그램은
>   화면·미리보기·정리·색 처리·내보내기를 담당합니다.
> * **클라우드 GPU 서버는 직접 준비해야 합니다** (아래 5번). 서버를 연결하기 전에는 **데모 모드**로 프로그램의 모든 기능을 써 볼 수 있습니다.
> * 데모 모드의 피규어는 AI가 만든 것이 **아닙니다**. 프로그램에 들어 있는 샘플이며 화면 곳곳에 `DEMO`라고 표시됩니다.
> * 이 프로그램은 OpenSCAD 같은 CAD 프로그램이 아니라, **유기적인 AI 피규어**용입니다.

## 1. 실행하기

### 포터블 폴더로 실행 (설치 필요 없음)
1. `FigureCraft-portable.zip`의 압축을 풉니다. (한글/공백이 없는 폴더를 권장: 예 `C:\FigureCraft`)
2. 폴더 안의 **`FigureCraft.exe`** 를 더블클릭합니다.
3. 처음 실행 시 Windows가 "PC 보호" 창을 띄우면 **추가 정보 → 실행** 을 누릅니다. (서명되지 않은 개인용 프로그램이라 나오는 안내입니다.)

설정·로그·프로젝트는 `%APPDATA%\FigureCraft` 에 저장됩니다 (프로젝트 폴더는 설정에서 바꿀 수 있어요).

### 직접 빌드하고 싶다면
`build_windows.bat` 를 더블클릭하세요. (Python 3.11 이상 필요) 결과물은 `output\FigureCraft\`, `output\FigureCraft-portable.zip`,
`output\BUILD_INFO.txt` 에 만들어집니다. Inno Setup 6이 설치돼 있으면 설치 프로그램(`FigureCraft-Setup.exe`)도 만듭니다.

## 2. 데모 모드로 먼저 써 보기 (GPU 없이, 무료)

프로그램을 처음 켜면 **데모 모드**입니다 (오른쪽 위에 `클라우드 GPU: 준비됨 · DEMO`).

1. 왼쪽 **[예시 프롬프트 넣기]** → **[피규어 생성]** 을 누릅니다.
2. 약 20초 동안 11단계(프롬프트 분석 → … → 준비 완료)가 차례로 표시됩니다. 퍼센트 숫자는 거짓으로 꾸미지 않고 단계로만 보여줍니다.
3. 가운데 3D 화면에서 돌려 보고, 오른쪽에서 색을 바꾸고 내보내기를 해 볼 수 있습니다.
4. 프롬프트에 "드래곤/판타지"를 쓰면 아기 드래곤, "크리스마스/장식"을 쓰면 트리 장식, 그 외에는 고양이 마법사 샘플이 나옵니다.

데모 모드에서도 **3D 뷰어, 색 설정, 내보내기, 프로젝트 라이브러리, Bambu Studio 열기**를 모두 시험할 수 있습니다.

## 4. 색상 (최대 4색, Bambu AMS)

AI가 만든 복잡한 텍스처 색을 **프린터가 쓸 수 있는 1~4색**으로 줄입니다.
* 색은 화면 캡처가 아니라 **실제 3D 메시의 면(삼각형)** 에 붙어 있습니다.
* 지각적 색 거리(CIELAB)로 비슷한 색을 묶는 K-means 방식이며, 아주 작은 얼룩은 자동으로 정리합니다.
* 프롬프트에 쓴 색(예: 보라색, 아이보리)이 있으면 그 색에 맞춰 정리합니다.
* **자동 팔레트 / 사용자 팔레트** 중 선택. 사용자 팔레트의 기본 색은 설정의 *AMS 색상 프리셋*입니다.
* 오른쪽 위 **[원본 색 · 1색 · 2색 · 3색 · 4색]** 으로 미리보기합니다.
* 각 색(AMS 1~4)마다 색 바꾸기(네모 클릭) · 이름 바꾸기(✎) · 보이기 · 잠금(🔒) · 병합(⇄) · 삭제(✕)가 있습니다.
* **파트 표**: 같은 색으로 이어진 영역 목록입니다. 표에서 고르거나 3D 화면을 클릭한 뒤, 오른쪽 드롭다운에서 AMS 색을 바꿀 수 있습니다.

## 5. 클라우드 GPU 연결 (실제 AI 생성)

> 서버(워커) 설치·실행 방법은 **`cloud-worker/README_KR.md`** 에 자세히 있습니다. 여기서는 연결 방법만 설명합니다.
> **이 저장소에서는 실제 RunPod 계정/GPU로 시험하지 못했습니다.** 처음 연결할 때는 짧은 테스트 생성부터 해 보세요.

### 5-1. RunPod 연결
**방법 A – Pod (직접 켜고 끄는 서버, 초보자에게 추천)**
1. RunPod에서 GPU Pod를 만들고 `cloud-worker` Docker 이미지를 실행합니다. HTTP 포트는 `8000`, 환경변수에 `WORKER_API_KEY`(긴 비밀번호), `ENGINE=trellis` 를 넣습니다.
2. Pod 주소는 `https://<POD_ID>-8000.proxy.runpod.net` 형태입니다.
3. FigureCraft → **설정 → 클라우드 GPU**
   * 공급자: **RunPod**
   * 엔드포인트 URL: 위 Pod 주소
   * API 키: 위에서 정한 `WORKER_API_KEY` (워커 전용 비밀번호)
   * RunPod Pod ID: Pod 번호 (자동 시작/종료에 사용)
   * RunPod 계정 API 키: RunPod → Settings → API Keys 에서 발급한 키 (Pod를 시작/종료할 때만 사용. 워커 키와 **다른 키**입니다)
   * 모델 엔진: **TRELLIS** (MIT 라이선스)
4. **[연결 테스트]** → "연결됨"이 나오면 성공입니다. 그 다음 **[설정 저장]**.

**방법 B – Serverless (일할 때만 켜지는 방식)**
1. RunPod → Serverless → New Endpoint → 같은 이미지, 시작 명령 `python -u runpod_handler.py`.
2. FigureCraft 설정: 공급자 **RunPod**, 엔드포인트에 **Endpoint ID**, API 키에 **RunPod API 키**(RunPod 계정 설정에서 발급), Pod ID는 비워 둡니다.

**방법 C – 일반 HTTP 서버**: 공급자 *일반 HTTP GPU 서버*, 엔드포인트 URL과 API 키만 입력하면 됩니다.

> API 키는 **이 PC에서 암호화**되어 저장되고 로그에 남지 않습니다. 원하면 환경변수 `FIGURECRAFT_API_KEY` 로 줄 수도 있습니다. 키를 파일에 직접 쓰거나 GitHub에 올리지 마세요.

### 5-2. 참조 이미지 (Image + Text)
서버가 이미지 입력을 지원할 때만 켜집니다. 지원하지 않으면 버튼이 비활성화되고 이유가 표시됩니다 (데모 모드는 지원 안 함).
이미지는 업로드 전에 크기가 줄고 EXIF 같은 정보가 제거됩니다.

### 5-3. 요금은 어떻게 나가나요? (GPU 끄는 법)
* **Pod**: 켜져 있는 동안 *아무 일도 안 해도* 시간(초) 단위로 계속 요금이 나갑니다. 꺼 두면(Stop) 저장공간 요금만 나옵니다.
* **Serverless**: 작업을 처리한 시간(과 대기 시간)에 대해서만 나갑니다. 일이 없으면 0대로 줄어듭니다.
* 정확한 금액은 runpod.io의 최신 가격표를 확인하세요 (자주 바뀝니다).

**요금을 아끼는 장치**
* **[생성 완료 후 GPU 자동 종료]** (기본 켜짐): 파일을 내려받자마자, 로컬 처리(복구·색 처리) 전에 GPU를 끕니다. 오류가 나거나 취소해도 끄려고 시도합니다.
* 화면 아래에 *시작 시각 · 완료 시각 · 추정 GPU 사용 시간*이 표시됩니다 (서버가 알려주면 그 값, 아니면 걸린 시간).
* 서버가 자동 종료를 지원하지 않으면 안내 창이 뜨고, 위쪽에 **[GPU 지금 종료]** 버튼이 나타납니다.
* 서버 쪽 안전장치: `IDLE_SHUTDOWN_MIN=10` 으로 일이 없으면 10분 뒤 스스로 꺼지게 할 수 있습니다 (프로그램이 먼저 꺼져도 안전).
* **그래도 마지막에는 RunPod 콘솔(runpod.io → Pods)에서 Pod가 *Stopped* 인지 꼭 확인하세요.**

## 6. 출력 준비 도구 (오른쪽)

* **메시 검사**: GOOD(양호) / CHECK(확인 필요) / FAILED(실패). 구멍·중복·퇴화 면·떠 있는 조각·비다양체 모서리·평평한 바닥·오버행·얇은 부분을 검사합니다.
  이 검사는 **추정**이며 슬라이서 분석이 아닙니다 → **출력 전 Bambu Studio에서 최종 확인하세요.**
* **안전 복구 실행**: 중복/퇴화 면 제거, 가까운 꼭짓점 병합, 면 방향 정리, 아주 작은 떠다니는 조각 제거, **작은** 구멍만 메우기. 큰 구멍은 일부러 건드리지 않습니다.
* **원본으로 되돌리기**: 내려받은 `original.glb` 상태로 돌아갑니다 (원본 파일은 항상 보존됩니다).
* **바닥 평평하게 (미리보기 → 적용)**: 빨간 면으로 자를 위치를 먼저 보여줍니다. 필요한 만큼만 얕게 자릅니다.
* **받침대 붙이기**: 원형/타원형/사각형/사용자 지정, 두께 기본 3 mm.
* **얇은 부분 보강**: 최소 중요 형상(기본 1.2 mm)보다 얇은 영역을 살짝 부풀립니다 (추정 방식, 닫힌 메시에서만).
* 노즐 0.4 mm · 최소 형상 1.2 mm · 권장 두께 1.5 mm 는 기본값이며 설정/왼쪽 패널에서 바꿀 수 있습니다.

### 모델 수정 요청과 버전
"귀를 더 크게 만들어줘" 같은 요청을 쓰고 **[수정 요청 보내기]** 를 누르면, 원래 프롬프트·이전 설정·참조 이미지와 함께 서버로 다시 보내
**새 버전**(v2, v3…)으로 저장합니다. 이전 버전은 절대 덮어쓰지 않으며 아래 목록에서 다시 열 수 있습니다.
(데모 모드는 모델을 실제로 고치지 못하고 요청 내용만 기록합니다.)

## 7. 내보내기

| 버튼 | 결과 | 색 정보 |
|---|---|---|
| **3MF 저장** (멀티파트 – 권장) | 색마다 *닫힌 솔리드 파트*로 나눈 3MF 한 개. 파트 이름 `AMS_1_IVORY`, `AMS_2_PURPLE` … | 파트별 색 |
| **3MF 저장** (색상 3MF) | 삼각형마다 색이 있는 3MF 한 개 | 삼각형별 색 |
| STL | 한 덩어리 STL (색 없음 – STL은 색을 저장할 수 없습니다) | 없음 |
| 색상별 STL | 색마다 STL 하나씩 (`…_AMS_1_IVORY.stl` …) | 파일별 |
| GLB / OBJ | 3D 뷰어·다른 프로그램용 (OBJ는 .mtl에 색) | 있음 |

* 3MF는 이름만 바꾼 파일이 아니라 **진짜 3MF 패키지**(단위 mm)입니다. 저장할 때마다 자동으로 다시 열어 검증합니다 (lib3mf).
* 모델이 닫힌 솔리드가 아니면 멀티파트가 *표면 조각*으로 만들어질 수 있고 이때 안내가 나옵니다. 슬라이서에서 "모델 수리"가 필요할 수 있습니다.

### Bambu Studio에서 열고 AMS 색 지정하기
1. 설정 → Bambu Studio → **[자동 감지]** (보통 `C:\Program Files\Bambu Studio\bambu-studio.exe`). 안 잡히면 **[찾아보기]** 로 직접 지정.
2. 오른쪽 아래 **[Bambu Studio에서 열기]** → 3MF를 저장하고 Bambu Studio를 실행합니다.
3. Bambu Studio에서 객체를 열면 `AMS_1_IVORY`, `AMS_2_PURPLE` … 처럼 **파트 목록**이 보입니다.
   각 파트를 선택해 오른쪽 *필라멘트* 에서 AMS 슬롯(1~4)의 실제 필라멘트를 지정하세요. (예: 파트 `AMS_2_PURPLE` → 보라색 필라멘트 슬롯)
4. 슬라이스 후 **출력 전에 Bambu Studio에서 최종 확인**합니다 (서포트, 얇은 부분, 색 교체 횟수).

> **알려진 한계**: Bambu Studio 버전에 따라 *색상 3MF*(삼각형별 색)를 무시하고 한 가지 색으로 열 수 있습니다. 그럴 때는 **멀티파트 3MF**를 쓰세요.
> 이 개발 환경에는 Bambu Studio가 없어서, 실제 Bambu Studio에서 열어 보는 시험은 하지 못했습니다.

### 한 가지 색으로만 출력할 때
**[STL]** 을 저장하고 어느 슬라이서에서든 여세요. 색 수를 1색으로 하고 싶으면 오른쪽 위 `1색` 을 누른 뒤 3MF를 저장해도 됩니다.

```
  versions/v1/ v2/ …           ← 버전별 전체 사본
```
라이브러리 탭에서 썸네일·제목·날짜·크기·색 수·상태를 보고 **열기 / 이름 변경 / 복제 / 삭제 / 내보내기(ZIP)** 할 수 있습니다.

## 9. 문제가 생겼을 때

오류 창에는 **[다시 시도] [로그 저장] [설정 열기]** 버튼이 있습니다. 로그: **도움말 → Open Log Folder** (API 키는 로그에 남지 않습니다).

| 증상 | 해결 |
|---|---|
| "GPU 서버에 연결할 수 없습니다" | 엔드포인트 주소 오타, Pod가 꺼져 있음, 방화벽을 확인. 설정에서 **연결 테스트** |
| "API 키가 올바르지 않습니다" | 서버의 `WORKER_API_KEY` 와 설정의 API 키가 같은지 확인 (RunPod Serverless는 RunPod API 키) |
| "응답 시간이 초과되었습니다" | 설정의 *제한 시간* 늘리기. 첫 생성은 모델 내려받기로 오래 걸릴 수 있음 |
| "다운로드가 중단되었습니다" | 자동으로 2번 이어받기를 시도합니다. 그래도 안 되면 [다시 시도] |
| "GLB 파일이 손상되었습니다" | 서버 로그 확인 후 다시 생성 |
| 3D 화면이 까맣게 나옴 | 그래픽 드라이버(AMD Adrenalin) 업데이트. 로그에 WebGL 오류가 남습니다 |
| "Bambu Studio를 찾을 수 없습니다" | 설정에서 `bambu-studio.exe` 경로를 직접 지정 |
| 디스크 공간 부족 | 프로젝트 폴더가 있는 드라이브를 비우거나 설정에서 폴더 변경 |
| 색이 이상하게 합쳐짐 | 오른쪽에서 색 수를 바꾸거나, 파트 표에서 영역별로 AMS 색을 지정 |

## 10. 개발자용 메모

* 구조: `desktop/` (Python 3.11 + PySide6 + Three.js 뷰어), `cloud-worker/` (FastAPI/RunPod 워커, 엔진 교체 가능).
* 공급자 인터페이스 `GenerationProvider` → `MockProvider`(데모), `GenericHttpProvider`, `RunPodProvider`. 새 클라우드를 붙이려면 이 인터페이스를 구현하세요.
* 3D 엔진 인터페이스 `ModelEngine` (워커): `generate_from_text / generate_from_image / generate_from_text_and_image`.
* 개발 실행: `pip install -r desktop/requirements-dev.txt` → `python desktop/run_figurecraft.py`
* 테스트: `python -m pytest desktop/tests -q` (워커를 실제로 띄워 프로토콜까지 시험합니다)
* 패키징 자체 시험: `FigureCraft.exe --self-test` (창 없이 데모 생성·색 줄이기·3MF 내보내기·검증을 수행)
